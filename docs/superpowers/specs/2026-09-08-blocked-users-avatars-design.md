# Спецификация: Отображение аватарок заблокировавших пользователей через t.me

## 1. Контекст и Проблема
В Telegram при блокировке пользователя другим пользователем сервер Telegram через MTProto перестаёт отдавать аватарку и статус онлайна заблокировавшего (`userProfilePhotoEmpty`). В клиенте вместо аватарки отображаются стандартные инициалы (буквенная заглушка).

Однако, если у заблокировавшего пользователя есть публичный юзернейм (`@username`), Telegram генерирует общедоступную веб-страницу предпросмотра профиля по адресу `https://t.me/<username>`. На этой странице без авторизации доступна актуальная аватарка в мета-теге `<meta property="og:image" ...>` или `<img class="tgme_page_photo_image" ...>`, размещённая на CDN Telegram (`telesco.pe`).

Данная функция позволяет AyuGram автоматически загружать и отображать эту аватарку, обходя ограничение блокировки.

---

## 2. Архитектура решения

### 2.1. Компонент `AyuAvatarResolver`
* **Расположение:** `Telegram/SourceFiles/ayu/features/avatars/ayu_avatar_resolver.h` и `.cpp`.
* **Назначение:** Очередь фоновых сетевых запросов к `t.me`, парсинг HTML, загрузка изображений и передача готовой аватарки в `UserData`.
* **Ограничения и безопасность:**
  * Ограничение параллельных запросов: не более 2 активных соединений одновременно.
  * Таймаут сетевого запроса: 5 секунд.
  * In-progress guard: предотвращение дублирующих запросов для одного и того же юзернейма.
  * Negative caching: если на `t.me` аватарки нет или юзернейм не существует — юзернейм заносится в кэш с TTL 2 часа, чтобы не спамить сервер.
  * Дисковый кэш: скачанные аватарки сохраняются локально в директорию кэша AyuGram, снижая сетевой трафик.

### 2.2. Сетевой пайплайн
1. Проверка локального дискового кэша: если аватарка для `@username` уже сохранена и валидна, читаем с диска без сетевого запроса.
2. HTTP GET `https://t.me/<username>` с эмуляцией User-Agent современного браузера.
3. Парсинг HTML:
   * Поиск ссылки в `<meta property="og:image" content="(https://cdn\d*\.telesco\.pe/file/[^"]+)"`.
   * Fallback поиск в `<img class="tgme_page_photo_image" src="(https://cdn\d*\.telesco\.pe/file/[^"]+)"`.
   * Исключение дефолтных иконок сайта Telegram (`telegram.org/img/...`, `.svg`).
4. HTTP GET изображения с CDN `telesco.pe`.
5. Сохранение файла на диск в кэш.
6. Передача в `UserData`:
   * Создание `InMemoryLocation` с байтами изображения.
   * `user->setUserpic(photoId, ImageLocation{InMemoryLocation, w, h}, false);`
   * `user->session().changes().peerUpdated(user, UpdateFlag::Photo);`

### 2.3. Точки триггера в коде
* `UserData::setPhoto`: когда приходит `MTPDuserProfilePhotoEmpty` и `!user->username().isEmpty()` (и аватарка ещё не установлена).
* При открытии профиля пользователя (`info_profile_widget` / `info_profile_top_bar`) или чата с пользователем без аватарки с юзернеймом.

### 2.4. Настройки AyuGram
* Добавление флага `loadBlockedAvatars` (по умолчанию: `true`) в `ayu_settings.h` / `ayu_settings.cpp`.
* Переключатель в UI настроек AyuGram:
  * Заголовок: «Загружать аватарки через t.me»
  * Описание: «Позволяет видеть аватарки пользователей, которые вас заблокировали, если у них установлен юзернейм.»

## 3. Обработка ошибок и крайних случаев
* **Пользователь без юзернейма:** `t.me` для таких пользователей не существует, запрос не отправляется.
* **Ошибка сети / 429 Too Many Requests / Таймаут:** Запрос мягко завершается, юзернейм временно помещается в negative cache на 15 минут, UI не зависает.
* **Пользователь разблокировал:** Если при обновлении данных от Telegram придет реальный `MTPDuserProfilePhoto`, MTProto-версия штатно заменит подставленную аватарку.
